# Git Version Control Notes

## 1. Project Version Control Approaches

### Storage Strategy for Changes
1. **Delta Storage (Storing Changes Only)**: When modifications are made to a completed project, only the newly modified parts or diffs are saved.
2. **Snapshot Storage (Full Version Storage)**: Whenever a project is modified and saved, the entire state of the project is captured and stored as a complete snapshot **(the approach used by Git)**.

### Version Repository Location
1. **Local**: All project modifications and version histories are managed and stored entirely on a single host machine.
2. **Centralized**: Project downloads and updates occur on local PCs, but versions are saved to a central server. The major vulnerability is a single point of failure—if the server goes down, the project version history becomes inaccessible.
3. **Distributed**: Every client keeps a full local copy of the repository's history in addition to a synchronized copy on a central server **(the approach used by Git)**.

Working Directory -> Staging Area -> Committed

## 3. Essential Git Commands & Configuration

| Command | Description |
| :--- | :--- |
| `git init` | Initializes a new local Git repository. |
| `git status` | Checks the current status of the repository and working tree. |
| `git add [filename]` | Stages specific files, moving them from the working directory to the staging area. |
| `git add .` | Stages all modified and new files in the current directory. |
| `git rm --cached [filename]` | Unstages a file, removing it from the staging area while keeping it in the working directory. |
| `git commit -m "commit message"` | Commits the staged files to the local repository along with a descriptive message. |
| `git branch -m [old-name] [new-name]` | Renames an existing branch to improve clarity and convention. |
