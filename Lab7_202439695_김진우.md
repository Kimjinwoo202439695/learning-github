# Open Source Software: Git Essentials & GitHub Integration

## 1. Core Git Concepts & Workflow
Git tracks changes across three primary states[cite: 2]:
* **Working Directory (Modified):** Files edited locally but not yet staged[cite: 2].
* **Staging Area (Staged):** Files marked to go into the next commit snapshot[cite: 2].
* **Repository (Committed):** Changes permanently stored in the `.git` directory[cite: 2].

---

## 2. Basic Command Reference

### Repository Initialization & Status
* `git init`: Initializes an empty Git repository in the current folder[cite: 3].
* `git status`: Checks the state of untracked, staged, or modified files[cite: 4].
* `git log`: Views commit history along with SHA-1 checksums[cite: 9, 16].

### Staging & Unstaging Files
* `git add <file>`: Stages a specific file[cite: 5].
* `git add .`: Stages all modified and untracked files in the directory[cite: 6].
* `git rm --cached <file>`: Removes a file from the staging area (untracks it) while keeping it in the local file system[cite: 12, 13].
* `git reset HEAD <file>` / `git restore --staged <file>`: Unstages a staged file without altering local modifications[cite: 18, 19].
* `git restore <file>`: Discards local changes in the working directory (unmodifies a file)[cite: 20].

### File & Branch Operations
* `git commit -m "message"`: Saves staged changes to the repository history[cite: 9].
* `git rm <file>`: Removes a file from both the repository and the local file system[cite: 11].
* `git mv <old_name> <new_name>`: Renames or moves a file within the repository[cite: 15].
* `git branch -m <old_name> <new_name>`: Renames an existing branch (e.g., `master` to `main`)[cite: 10].

## 3. Ignoring Files (`.gitignore`)
The `.gitignore` file specifies untracked file patterns that Git should ignore[cite: 7, 8]:
* `*.a`: Ignores all `.a` extension files[cite: 8].
* `!lib.a`: Tracks `lib.a` despite ignoring other `.a` files[cite: 8].
* `/TODO`: Ignores `TODO` file only in the current root directory[cite: 8].
* `build/`: Ignores all contents in any `build` directory[cite: 8].
* `doc/*.txt`: Ignores `.txt` files under `doc/` (not subdirectories)[cite: 8].
* `doc/**/*.pdf`: Ignores all `.pdf` files in `doc/` and any of its subdirectories[cite: 8].

## 4. Connecting to Remote Repositories (GitHub)

### Authentication & Token Creation
1. Navigate to **GitHub Settings → Developer Settings → Personal Access Tokens (classic)**[cite: 21, 22].
2. Generate a token with `repo` scope permissions[cite: 23].
3. Copy and save the generated Personal Access Token (PAT) securely[cite: 25].

### Pushing to Remote
1. Link local repository to GitHub:
   ```bash
   git remote add origin [https://github.com/username/repository-name.git](https://github.com/username/repository-name.git)
   ```[cite: 29]
2. Configure authentication URL with token if password authentication fails:
   ```bash
   git remote set-url origin [https://YOUR_TOKEN_ID@github.com/username/repository-name.git](https://YOUR_TOKEN_ID@github.com/username/repository-name.git)
   ```[cite: 29]
3. Push changes to remote:
   ```bash
   git push -u origin main
   ```[cite: 29]
